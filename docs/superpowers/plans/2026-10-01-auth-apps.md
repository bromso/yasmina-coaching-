# Authentication in `apps/auth` and `apps/app` (Phase 4b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `apps/auth`'s sign-in, sign-up, forgot-password and reset-password forms work against
`apps/api` through `@repo/session`; `apps/app` guards `/notes` and `/api/chat` with the real user
and offers sign-out; the follow-ups 4a left for 4b are closed.

**Architecture:** Each app owns one lazy `getAuth()` (`@repo/session`'s `createAuth`). Form logic
lives in pure, dependency-injected "action cores" (`apps/auth/src/lib/actions.ts`) tested under
`bun test` with a fake api; thin `"use server"` wrappers bind them to `getAuth()`, request headers
and `redirect()`. Forms are client components on `useActionState`. Sign-out is a server action in
every app that shows signed-in UI (a cross-subdomain POST to a `/logout` route would fail the
same-origin check by design).

**Tech Stack:** Next 16 App Router (server actions, `useActionState`, `instrumentation.ts`),
React 19, `@repo/session`, `@repo/api-contract` Zod schemas, `bun test`.

**Spec:** `docs/superpowers/specs/2026-09-30-authentication-design.md` (sub-project 4b; the
sign-out and `/logout` lines are amended by Task 5)

## Global Constraints

- Branch `feat/auth-apps` from `main` after PR #41 (4a). Dev hosts are `<name>.brand.localhost`; cookie domain `.brand.localhost` in dev.
- Every Next app that reads the session instantiates `@repo/session` exactly once, lazily, as `getAuth()` in `src/lib/auth.ts` (the README snippet). No app imports `next/headers` for auth outside that file and the action wrappers.
- Form validation uses the contract's Zod schemas (`SignInSchema`, `SignUpSchema`, `RequestPasswordResetSchema`, `ResetPasswordSchema`) via `safeParse` — no react-hook-form.
- Error copy is exact: sign-in failure `"Invalid email or password"`; throttled `"Too many attempts, try again later"`; duplicate email (field error on `email`) `"An account with this email already exists"`; bad reset link `"This reset link is invalid or has expired"`; api unreachable `"The sign-in service is unavailable right now. Try again in a moment."`; forgot-password always `"If an account exists for that email, a reset link is on its way."`.
- `requestPasswordReset` answers the same whatever the email; the forms never reveal account existence except sign-up's duplicate-email error (spec-mandated).
- `next=` is only ever consumed through `getAuth().safeNextUrl(...)`.
- Route handlers that mutate (`/api/chat`) call `assertSameOrigin(req)` before anything else.
- `x-api-client-id`: `session:<hash>` for signed-in calls (already in `@repo/session`); `anon:<sha256(ip) prefix>` for the anonymous auth calls (Task 1 adds the option).
- Production boot: each app's `instrumentation.ts` `register()` validates the auth env once (`assertAuthEnv`) so a deploy without `COOKIE_DOMAIN`/`AUTH_URL`/`APP_URL`/`API_URL`/`API_SERVICE_TOKEN` refuses to start; `next build` is unaffected (register runs at `next start`).
- Biome 0 errors / 0 warnings; double quotes, no semicolons, 2-space indent, 100-char lines. Commits: Conventional Commits, blank line, `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- `bun test scripts` must stay green after every root `package.json` script change (planner tests pin the filter lists).

## Review Focus

1. **A `next=` pointing off-site** (`https://evil.com`, `//evil.com`, `http://app.brand.localhost.evil.com`) must land on `APP_URL` — Task 2's action-core tests feed those through the injected `safeNextUrl` and assert the redirect target; `@repo/session`'s matrix (4a) covers the function itself.
2. **A cross-site POST to `/api/chat`** carrying the cookie must be refused before the AI service is called — Task 4's chat-proxy test with `Sec-Fetch-Site: cross-site` asserts 403 and zero upstream requests.
3. **Forgot-password for an unknown email** must look identical to a known one in the UI — Task 2's action-core test asserts the same state object for both fake-api outcomes (resolve and reject).
4. **A production start with a missing auth variable** must fail at boot, not on the first request — Task 1's `assertAuthEnv` test plus Task 3/4's `instrumentation.ts` wiring.
5. **A signed-out user opening `/notes`** must be redirected to `auth` with the original URL in `next=` and come back after sign-in — Task 5's browser walk.

```ts
export type ApiClientOptions = {
  apiUrl: string
  serviceToken: string
  sessionToken?: string | null
  /** Rate-limit key for calls without a session (see anonymousClientId); a session id wins. */
  clientId?: string
  fetch?: typeof fetch
  timeoutMs?: number
}

const hashPrefix = async (value: string) => {
  const digest = await crypto.subtle.digest("SHA-256", new TextEncoder().encode(value))
  return Array.from(new Uint8Array(digest), (b) => b.toString(16).padStart(2, "0")).join("").slice(0, 32)
}

/** `session:<hash>`: one rate-limit bucket per signed-in session, never the raw token. */
export const sessionClientId = async (token: string) => `session:${await hashPrefix(token)}`

/** `anon:<hash>`: one bucket per browser ip for sign-in/up and password-reset calls. */
export async function anonymousClientId(ip: string | null | undefined): Promise<string | undefined> {
  return ip ? `anon:${await hashPrefix(ip)}` : undefined
}
```

```ts
/** What the sessions list will show for this sign-in. Informational; never trusted for auth. */
export function requestInfo(h: Headers): { userAgent?: string; ip?: string } {
  const userAgent = h.get("user-agent")?.slice(0, 500) || undefined
  const forwarded = h.get("x-forwarded-for")?.split(",")[0]?.trim()
  const ip = (forwarded || h.get("x-real-ip") || undefined)?.slice(0, 45)
  return { userAgent, ip }
}
```

`apps/auth/src/lib/actions.ts`:

```ts
import { ORPCError } from "@orpc/client"
import {
  type ApiClient,
  RequestPasswordResetSchema,
  ResetPasswordSchema,
  SignInSchema,
  SignUpSchema,
} from "@repo/api-contract"

export type FormState =
  | { ok: false; message?: string; fieldErrors?: Record<string, string>; values?: Record<string, string> }
  | { ok: true; message?: string }

export type AuthApi = Pick<ApiClient["auth"], "signIn" | "signUp" | "requestPasswordReset" | "resetPassword">

/** Everything a form action needs, injected so the cores run under bun test with a fake api. */
export type ActionDeps = {
  api: AuthApi
  setSession(session: { token: string; expiresAt: string }): Promise<void>
  safeNextUrl(candidate: string | null | undefined): string
  client: { userAgent?: string; ip?: string }
}

export const UNAVAILABLE = "The sign-in service is unavailable right now. Try again in a moment."
export const RESET_SENT = "If an account exists for that email, a reset link is on its way."

const str = (fd: FormData, key: string) => {
  const v = fd.get(key)
  return typeof v === "string" ? v : ""
}

export function fieldErrors(issues: ReadonlyArray<{ path: PropertyKey[]; message: string }>) {
  const out: Record<string, string> = {}
  for (const issue of issues) {
    const key = String(issue.path[0] ?? "form")
    out[key] ??= issue.message
  }
  return out
}

/** A declared api error with one of the given codes, else undefined (anything else is "unavailable"). */
function apiError(error: unknown, codes: string[]) {
  return error instanceof ORPCError && codes.includes(error.code) ? error : undefined
}

export async function signInCore(deps: ActionDeps, fd: FormData): Promise<FormState | { redirectTo: string }> {
  const values = { email: str(fd, "email") }
  const parsed = SignInSchema.safeParse({ email: values.email, password: str(fd, "password"), client: deps.client })
  if (!parsed.success) return { ok: false, fieldErrors: fieldErrors(parsed.error.issues), values }
  try {
    const { session } = await deps.api.signIn(parsed.data)
    await deps.setSession(session)
    return { redirectTo: deps.safeNextUrl(str(fd, "next")) }
  } catch (error) {
    const known = apiError(error, ["UNAUTHORIZED", "TOO_MANY_REQUESTS"])
    return { ok: false, message: known?.message ?? UNAVAILABLE, values }
  }
}

export async function signUpCore(deps: ActionDeps, fd: FormData): Promise<FormState | { redirectTo: string }> {
  const values = { name: str(fd, "name"), email: str(fd, "email") }
  const parsed = SignUpSchema.safeParse({ ...values, password: str(fd, "password"), client: deps.client })
  if (!parsed.success) return { ok: false, fieldErrors: fieldErrors(parsed.error.issues), values }
  try {
    const { session } = await deps.api.signUp(parsed.data)
    await deps.setSession(session)
    return { redirectTo: deps.safeNextUrl(str(fd, "next")) }
  } catch (error) {
    const conflict = apiError(error, ["CONFLICT"])
    if (conflict) return { ok: false, fieldErrors: { email: conflict.message }, values }
    return { ok: false, message: UNAVAILABLE, values }
  }
}

export async function forgotPasswordCore(deps: ActionDeps, fd: FormData): Promise<FormState> {
  const parsed = RequestPasswordResetSchema.safeParse({ email: str(fd, "email") })
  if (!parsed.success) {
    return { ok: false, fieldErrors: fieldErrors(parsed.error.issues), values: { email: str(fd, "email") } }
  }
  // Whatever the api says (including nothing, because it is down), the user sees the same sentence.
  await deps.api.requestPasswordReset(parsed.data).catch((error) => console.error("[auth] forgot failed", error))
  return { ok: true, message: RESET_SENT }
}

export async function resetPasswordCore(deps: ActionDeps, fd: FormData): Promise<FormState | { redirectTo: string }> {
  const password = str(fd, "password")
  if (password !== str(fd, "confirm")) return { ok: false, fieldErrors: { confirm: "Passwords do not match" } }
  const parsed = ResetPasswordSchema.safeParse({ token: str(fd, "token"), password })
  if (!parsed.success) return { ok: false, fieldErrors: fieldErrors(parsed.error.issues) }
  try {
    await deps.api.resetPassword(parsed.data)
    return { redirectTo: "/login?reset=1" }
  } catch (error) {
    const bad = apiError(error, ["BAD_REQUEST"])
    return { ok: false, message: bad?.message ?? UNAVAILABLE }
  }
}
```

(`ORPCError` from `@orpc/client` is the same class the typed client throws; `defined` errors keep
the server's message.) `apps/auth/src/instrumentation.ts`: the README snippet from Task 1.
