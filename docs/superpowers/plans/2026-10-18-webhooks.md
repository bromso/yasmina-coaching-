# Outgoing Webhooks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Workspace admins on a paid plan register HTTPS endpoints that receive Standard-Webhooks-signed workspace events, delivered on the job queue behind an SSRF guard, with retries, auto-disable and a delivery log.

**Architecture:** `webhook_endpoints` / `webhook_deliveries` + an SSRF guard + a signer in `apps/api/src/webhooks/`; `workspaces.webhooks.*` procedures; `emitWebhookEvent` called by the existing emitters; a `webhook.deliver` job using Bun `fetch` pinned to the checked address; event schemas in `@repo/public-api-contract/webhooks`; a Webhooks card in `apps/account`.

**Tech Stack:** Bun.sql (SQLite + Postgres), oRPC, the job queue, Bun `fetch` (`tls.serverName`, `proxy: false`, `redirect: "manual"`), Next 16 + next-intl, Playwright; `standardwebhooks` as a devDependency of `apps/api` only.

**Spec:** `docs/superpowers/specs/2026-10-18-webhooks-design.md`

## Global Constraints

- Migration `0028_webhooks`: `webhook_endpoints` (`id`, `workspace_id` ON DELETE CASCADE, `url` ≤ 2000, `description` ≤ 200 nullable, `events` JSON ≥ 1, `secret` AES-256-GCM `v1:<iv>:<ct>` under `TWO_FACTOR_ENCRYPTION_KEY`, `created_by` nullable no FK cascade, `created_at`, `enabled`, `consecutive_failures`, `disabled_at`, `disabled_reason` `failures|gone|manual|null`; index `workspace_id`) and `webhook_deliveries` (`id`, `endpoint_id` ON DELETE CASCADE, `event_id`, `event_type`, `attempt`, `status` nullable, `error` `timeout|network|blocked|redirect|http|null`, `duration_ms`, `created_at`; index `(endpoint_id, created_at)`).
- Signing (Standard Webhooks): secret `whsec_` + base64 of 32 random bytes; headers `webhook-id` (`msg_<base64url 16 bytes>`), `webhook-timestamp` (unix seconds), `webhook-signature` `v1,<base64 HMAC-SHA256(key, "id.timestamp.body")>`, the body the exact minified JSON sent.
- Events: `note.created`, `note.deleted`, `member.joined`, `member.left`, `member.role_changed`, `workspace.updated`, `api_key.created`, `api_key.revoked`, `ping`; envelope `{ type, timestamp, data }`; data as the spec lists; never emails; `WEBHOOK_EVENTS` + schemas in `@repo/public-api-contract/webhooks`.
- Rules: `member("admin")`; create/update/rotateSecret need the `api` feature; list/deliveries/delete on every plan; all but list/deliveries refused while impersonating; max **10** endpoints (workspace-row lock); `https` only, no userinfo/fragment, ≤ 2000; outside production `http` to `*.localhost` allowed.
- SSRF guard: resolve all A/AAAA; refuse any non-public address (the spec's full range list incl. IPv4-mapped/compatible); delivery dials only checked addresses via Bun `fetch` with `Host` + `tls.serverName`, `proxy: false`, `redirect: "manual"`, 10 s timeout; never stores or returns a response body.
- Delivery: `webhook.deliver` `maxAttempts` 8; 2xx success (reset failures); 410 → disable `gone`; else record + throw; a delivery row per attempt; job death increments `consecutive_failures`, at 5 → disable `failures`, mail owner `webhookDisabled` (en + sv), audit. `webhooks.prune` `55 3 * * *` (30 days).
- Commit trailer exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; Conventional Commits ≤ 100 chars; Biome clean, zero warnings; parallel agents commit with `git commit --only <paths>`; fake secrets in tests carry `// gitleaks:allow` in the commit that adds them. Implementers never run Playwright, `bun run ci`/`validate`, or any docker command. Client components import contract values only via Zod-free subpaths and never `@repo/sites` root.

## Review Focus

1. A URL whose DNS answers public at save time and private at delivery (rebinding), or that redirects to an internal address → never dialled (Tasks 1–2).
2. A delivery after the endpoint is disabled/deleted, unsubscribed, or the workspace lost the `api` feature → nothing sent (Task 2).
3. The secret leaking: list responses, audit metadata, delivery rows, logs, the data export (Tasks 1–2).
4. A change that rolls back still emitting, or an emitter firing twice → exactly once, only after commit (Task 2).
5. Our signature not verifying with the official `standardwebhooks` library for a body with non-ASCII text (Task 1).
