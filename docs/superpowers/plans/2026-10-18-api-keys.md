# API Keys and /v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Workspace admins on a paid plan create scoped, expiring API keys, and outside tools use them against a small versioned `/v1` REST API (workspace, members, notes) generated from its own contract.

**Architecture:** `api_keys` table + key core (format, hash, parse) + `workspaces.apiKeys.*` procedures in `apps/api`; a new `@repo/public-api-contract` package served by a second oRPC `OpenAPIHandler` on `/v1/*` behind its own api-key guard and per-key limiter; an API keys card in `apps/account` and "via API key" notes in `apps/app`.

**Tech Stack:** Bun.sql (SQLite + Postgres), oRPC (`OpenAPIHandler`, `OpenAPIGenerator`), Zod, Next 16 + next-intl, Playwright, Gitleaks. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-18-api-keys-design.md`

## Global Constraints

- Migration `0027_api_keys`: `api_keys` (`id`, `workspace_id` ON DELETE CASCADE, `name` 1–60, `prefix` 8 chars UNIQUE, `secret_hash` SHA-256 hex, `scopes` JSON text, `created_by` nullable no FK cascade, `created_at`, `expires_at` nullable, `last_used_at`, `revoked_at`; index on `workspace_id`) and `notes.api_key_id` INTEGER nullable.
- Key format `bb_live_<prefix>_<secret>`: prefix 8 base62 chars, secret 32 random bytes base64url; stored as SHA-256 of the whole key; full key returned only by `create`; constant-time compare.
- Scopes `workspace:read`, `members:read`, `notes:read`, `notes:write` (`API_SCOPES`); at least one. `api` joins `FEATURES` (Pro, Team) with a `FEATURE_MESSAGES` entry.
- `workspaces.apiKeys.list/create/revoke` (⚑, `member("admin")`): `create({ workspaceId, name, scopes, expiresInDays: 30 | 90 | 365 | null })` needs the `api` feature, max 20 live keys (`CONFLICT`); create/revoke refused while impersonating; audit `workspace.api_key_created` / `workspace.api_key_revoked`.
- `/v1/*`: `Authorization: Bearer bb_live_…` only (no service token, no session); `401 unauthorized` for malformed/unknown/revoked/expired/feature-lost; revoked-key use recorded to telemetry without key material; `last_used_at` at most once a minute per key; limiter `api-key:<id>` 600/min → `429 rate_limited` + `Retry-After`; never logged.
- Errors `{ "error": { "code", "message" } }`: `unauthorized` 401, `forbidden_scope` 403 (names the scope), `not_found` 404, `validation_failed` 400, `rate_limited` 429, `internal` 500. Cross-workspace ids → 404.
- Routes: `GET /v1/workspace` (`workspace:read`) `{ id, name, slug, plan }`; `GET /v1/members` (`members:read`) `{ items: [{ userId, name, role, joinedAt }], nextCursor }` no emails; `GET /v1/notes`, `GET /v1/notes/{id}` (`notes:read`) note `{ id, title, body, createdAt, author: { type: "user", id, name } | { type: "api_key", id, name } | null }`; `POST /v1/notes { title, body }`, `DELETE /v1/notes/{id}` (`notes:write`); `limit` 1–100 default 25. `/v1/openapi.json` and `/v1/docs` open.
- Commit trailer exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; Conventional Commits ≤ 100 chars; Biome clean, zero warnings. Implementers never run Playwright, `bun run ci`/`validate`, or any docker command. Client components import contract values only via Zod-free subpaths and never `@repo/sites` root.

## Review Focus

1. A key from workspace A naming an id from workspace B (note get/delete, members cursor) → `404 not_found`, never data (Task 2).
2. A key used after revocation, after expiry, or after the workspace drops to Free → `401` immediately, no cache window (Task 2).
3. A key, or its hash, appearing anywhere it should not: logs, audit metadata, telemetry, list responses, the data export (Tasks 1–2).
4. Concurrent `create`s at 19 live keys → never 21 (Task 1, Postgres race test).
5. A note created by a key showing correctly everywhere it renders (`/notes`, realtime, the internal list) and surviving the key's revocation (Tasks 2–3).
