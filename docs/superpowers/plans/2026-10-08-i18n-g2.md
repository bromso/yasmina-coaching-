# i18n G2 — app, account, the static apps' switcher — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish i18n: `apps/app` and `apps/account` fully in English and Swedish (with a
**Language** card in account), the static apps' language switcher, `x-locale` from `www`'s waitlist,
and the G1 follow-ups — completing Phase 7.

**Architecture:** Each signed-in app repeats G1's `apps/auth` pattern (next-intl without routing,
`src/i18n/request.ts` from `getAuth().getLocale()`, the provider, `<html lang>`, a header
`LocaleSwitcher` posting to a `setLocale` action, action cores taking a locale, Zod issues mapped by
code). A new `packages/i18n-guard` holds the AST guard so every translated app runs its own guard
test. The static apps get a client-only switcher that writes the shared cookie and stays static.

**Tech Stack:** next-intl 4.14.9 / use-intl 4.14.9 (already catalogued), Next 16.2, React 19.2,
Bun 1.4.2, the `typescript` compiler API, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-08-i18n-design.md` (G2 in §3). G1 (#76) is merged; its
`apps/auth`, `@repo/i18n`, `@repo/session` and `docs/guides/i18n.md` are the template.

## Global Constraints

- Biome clean with zero warnings; double quotes, no semicolons, 2-space indent, 100-char lines.
- Conventional Commits, header ≤ 100 chars, one type per header; every commit message ends with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- No new npm dependencies (`typescript` for `packages/i18n-guard` via `catalog:` if the catalog has
  it, else the root devDependency it already resolves to — no version change).
- English stays byte-identical in every app's default render and in every `@repo/ui` default; new
  label props default to today's exact strings.
- Natural Swedish; `{placeholders}` kept; ICU for plurals ("1 person här" / "{count} personer här").
- Never compare an api message's text; never render an `@repo/api-contract` English constant as copy
  in a Next app — use a catalog key.
- Dates keep `timeZone: "UTC"` (server and client renders must agree); only the locale changes.
- The static apps stay static (`○`); their copy stays English.
- No root `loading.tsx`; no `@repo/ui` dependency on next-intl.

## Review Focus

1. **A Swedish user on a page that mixes server and client text** (notes list re-rendered live by
   `LiveNotes`, the 2FA card) — no hydration mismatch, no English fragments. (Task 2/3 tests)
2. **A Swedish user who hits the chat upsell or a seat limit** — the 403 / limit message is Swedish,
   not the contract's English constant. (Task 2/4 tests)
3. **Switching language on a static page** — the cookie is written for every subdomain, the page
   stays English with a short notice, and the next visit to `app` is Swedish. (Task 5 e2e)
4. **The Language card** — saving re-renders the account page in the new language in the same
   request, and a failure shows a message (not an error page). (Task 3 test + e2e)
5. **An action that calls the api more than once** — at most one `auth.me` for the locale per
   request. (Task 1 test)
