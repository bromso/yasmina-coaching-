# The legal app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static, bilingual `apps/legal` (modelled on `apps/blog`) that becomes the only home of the privacy, terms, accessibility and company pages; every app links to it, www's old pages redirect, and booking asks for consent to the terms.

**Architecture:**
- **Pure core.** A pure `createLegal` in `@repo/content` validates the MDX pages: change logs, translation parity and placeholders.
- **Page addresses.** `@repo/sites/legal` owns the page ids, the paths and `legalUrl()`. Every app, the api and email link through it.
- **The app.** `apps/legal` renders the pages in the shared look, with `(sv)` and `(en)` root layouts. A `LEGAL_DRAFT` switch adds a draft notice and `noindex`.

**Tech Stack:** Next 16, fumadocs-mdx, Bun test, Playwright, oRPC + Zod, React Email, Biome.

**Spec:** `docs/superpowers/specs/2026-11-12-legal-app-design.md`

## Global Constraints

- **Pages and addresses** (from the spec):
  - Swedish at `/integritet`, `/villkor`, `/tillganglighet`, `/foretaget`; English at `/en/privacy`, `/en/terms`, `/en/accessibility`, `/en/company`.
  - `/` and `/en` list the four pages with their "Last updated" dates.
  - The cookie list is a section of the privacy page, at `#cookies`.
- **Placeholders** are written `[ATT FYLLA: …]` in Swedish files and `[TO FILL: …]` in English files. They render highlighted. They never fail a build.
- **Change log:** every page has `changes: { date, summary }[]`, newest first, at least one entry. "Last updated" is `changes[0].date`. A translation's newest date equals its source's.
- **Draft mode:** `LEGAL_DRAFT` is on unless set to `"false"`. On, every page shows "Utkast – granskas juridiskt" or "Draft – under legal review", the app sends `noindex`, and robots disallows `/`.
- **Launch scope:** the texts describe www, blog, auth, app, account, api and legal. Docs, help, jobs and ai are not described. Processors named as certain are mail (Resend or SMTP) and the hosting server. Stripe, S3-style storage and Google/GitHub/Apple sign-in are placeholders. Sentry, PostHog, Plausible and Anthropic are left out.
- **No invented facts.** No org. number, address, legal basis, retention or provider the code doesn't back; use a placeholder instead.
- **Retention figures** (from the code): leads 12 months; audit log 365 days with ip and user agent removed at 90; raw analytics 90 days; telemetry errors 30 days and vitals 7; data exports 7 days; account deletion 7 days after the request. Bookings get a placeholder, because no prune job exists.
- **Copy:** natural Swedish written as Swedish, not a translation. No exclamation marks. No AI tells (`.claude/skills/copywriting/references/ai-tells.md`).
- **Legal references:** checked with Legal Data Hunter's `resolve_reference` (SE or EU, `legislation`). A claim that can't be confirmed gets a placeholder.
- **Look:** no app styling (`scripts/app-styles.test.ts`). Every look piece comes from `@repo/ui` and the tokens.
- **Process:**
  - Never push; commit only on `feature/legal`. Commit messages are Conventional Commits ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  - Never stop or kill a process you didn't start; the user's `bun dev` may hold ports 3000–3010. Run e2e and servers in a scratchpad worktree, and only when the ports are free.
  - Each task runs `bun test scripts`, `bunx biome ci .` (0 errors, 0 warnings) and `bun run typecheck` before committing.

## Review Focus

1. **www's old URLs follow the reader's language.** A visitor with `locale=en` opening www `/privacy` lands on `/en/privacy`; without the cookie, on `/integritet`. Pinned in Task 4.
2. **A malformed or wrong-language placeholder.** `[ATT FYLLA x]` (no colon) or `[TO FILL: …]` in a Swedish file is reported as a content problem, not silently rendered as final text. Pinned in Task 1.
3. **Booking without JavaScript, box unticked.** The server answers with a field error on `terms`, and the visitor's other answers stay filled in. Pinned in Task 5.
4. **One language updated, the other forgotten.** A page whose Swedish change log has a newer date than its English one fails the build. Pinned in Task 1.
5. **Staging host prefix.** With `SITE_HOST_PREFIX=yas-`, `legalUrl` gives `https://yas-legal.<domain>/…`, so emails and footers on staging point to the staging legal app. Pinned in Task 2.

### Task 1: `createLegal` in `@repo/content`

**Files:**
- Modify: `packages/content/src/schema.ts` (add the legal schema), `packages/content/package.json` (export `./legal`).
- Create: `packages/content/src/legal.ts`, `packages/content/src/legal.test.ts`.

**Interfaces:**
- Produces:
  - `legalFrontmatterSchema`: a `z.strictObject` with `title`, `description` (non-empty), `locale: z.enum(POST_LOCALES)`, `page: z.string().min(1)`, and `changes: z.array(z.strictObject({ date: dateSchema, summary: z.string().min(1) })).min(1)`. Type `LegalFrontmatter`.
  - `type LegalPageMap = Record<string, Record<PostLocale, string>>`, mapping a page id to its slug per locale.
  - `type LegalInput = { file: string; slug: string; frontmatter: unknown; text: string }`.
  - `type LegalDoc = Omit<LegalFrontmatter, "changes"> & { changes: { date: Date; summary: string }[]; slug: string; url: string; updated: Date; placeholders: string[] }`.
  - `PLACEHOLDER_PATTERN`, and `findPlaceholders(text: string): { text: string; locale: PostLocale | null; valid: boolean }[]`. A match counts as anything beginning `[ATT FYLLA` or `[TO FILL`. It is valid only when written `[ATT FYLLA: <non-empty>]` or `[TO FILL: <non-empty>]`.
  - `createLegal(inputs: LegalInput[], pages: LegalPageMap, options: { rootLocale: PostLocale }): Legal`, where:
    ```ts
    interface Legal {
      docs(): LegalDoc[]
      doc(page: string, locale: PostLocale): LegalDoc
      inLocale(locale: PostLocale): LegalDoc[]
      translation(doc: LegalDoc): LegalDoc
      placeholders(): { file: string; text: string }[]
    }
    ```
    The url is `"/" + slug` for the root locale and `"/en/" + slug` otherwise; use `localePrefix`. `docs()` sorts by the key order of `pages`.
  - **Validation:** collect every problem, then throw one `ContentError(problems)`. Each problem names the file. The problems are:
    - invalid frontmatter;
    - an unknown `page`;
    - a slug that differs from `pages[page][locale]`;
    - a duplicate page and locale pair;
    - a page missing in either locale;
    - `changes` not sorted newest first;
    - a translation whose `changes[0].date` differs from the root-locale doc's;
    - an invalid placeholder;
    - a placeholder in the other language's form (`[TO FILL: …]` in an `sv` file, `[ATT FYLLA: …]` in an `en` file).

- [ ] **Step 1: Write failing tests** in `legal.test.ts`. Use a fixture `PAGES = { privacy: { sv: "integritet", en: "privacy" }, terms: { sv: "villkor", en: "terms" } }` and a `doc(overrides)` helper that builds a valid input. Tests:
  - `"builds both languages with urls and updated dates"`: `doc("privacy","sv").url === "/integritet"`; `doc("privacy","en").url === "/en/privacy"`; `updated` equals `changes[0].date`.
  - `"translation pairs a page across locales"`: `translation(sv).locale === "en"`.
  - `"reports every problem at once"`: given one unknown page, one slug mismatch and one missing translation, a single thrown `ContentError` has 3 problems, each containing its file.
  - `"a change log must be newest first and non-empty"`: `changes: []` fails; `[2026-01-01, 2026-02-01]` fails.
  - `"a translation updated in one language only fails"` (Review Focus 4): sv newest `2026-11-12` against en newest `2026-11-01` gives a problem naming both files.
  - `"placeholders are listed, and malformed or wrong-language ones fail"` (Review Focus 2):
    - `findPlaceholders("a [ATT FYLLA: org.nr] b")` returns one valid `sv` match.
    - `"[ATT FYLLA org.nr]"` is invalid.
    - `[TO FILL: x]` inside an `sv` doc is a problem.
    - `placeholders()` lists `{ file, text }` for every valid one.
- [ ] **Step 2:** Run `bun test packages/content/src/legal.test.ts`; expect it to fail with "cannot find module".
- [ ] **Step 3:** Implement in `legal.ts`, reusing `ContentError`, `localePrefix` and `dateSchema`. Export it from `package.json` as `"./legal": "./src/legal.ts"`.
