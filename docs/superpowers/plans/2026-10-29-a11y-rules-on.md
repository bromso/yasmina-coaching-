> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Biome's four repo-wide-disabled a11y rules (and `useValidAnchor`) back on at `error`, with every first-party violation fixed and vendored exemptions narrowed to named rules with reasons.

**Architecture:** Fix the 11 first-party findings in `packages/ui` (semantic element where it is a true equivalent, else a per-line reasoned `biome-ignore`); delete `biome.json`'s top-level `linter.rules.a11y` block; in vendored files apply only behaviour-keeping fixes and list whatever rules still fail in the existing vendored override with a comment.

**Tech Stack:** Biome 2.6, React 19, shadcn/ui components in `packages/ui`, Storybook stories in `apps/story`.

**Spec:** `docs/superpowers/specs/2026-10-29-tech-debt-sweep-design.md` (section 14A). Plans for 14B–14D follow once 14A merges.

## Global Constraints

- Branch `chore/phase-14a-a11y` (the spec commits are already on it). Biome clean: `bunx biome ci .` reports no errors, warnings or infos.
- No product behaviour changes: each component renders the same, its existing tests and stories pass; a DOM change is only a semantic equivalent (`<div role="region" aria-label>` → `<section aria-label>`).
- `role="group"` on a `<div>` is the WAI-ARIA group pattern and is **kept** (a `<fieldset>` brings form semantics and default styling the component does not want) — with `// biome-ignore lint/a11y/useSemanticElements: <reason>` on the line, the reason naming why `<fieldset>` is wrong there. Same for any other site where the suggested element is not a true equivalent.
- Vendored files = `packages/ui/src/components/{animate-ui,magicui,charts}/**` plus the PascalCase top-level `.tsx` files the vendored override lists. Fix only with behaviour-keeping changes (an explicit `role`, `type="button"`, a matching `onKeyDown` that triggers the same handler for Enter/Space); never restructure a vendored component.
- Never accept a Biome `--unsafe` fix without reading the diff (Phase 13's sweep: one changed a string comparison to `Math.min`).
- Commit trailer exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; Conventional Commits ≤ 100 chars; `git commit --only <paths>`; run `bun scripts/security/secrets.ts --range $(git merge-base origin/main HEAD)..HEAD` before handing back. Implementers never run Playwright, `bun run ci`/`validate`, or docker; the controller runs the full gate.

## Review Focus

1. A `biome-ignore` that hides a real problem: each must name why the suggested element or handler is wrong at that site, not restate the rule (Tasks 1–2).
2. A semantic swap that changes layout or styling (`<section>`/`<fieldset>` default margins, borders, `display`) — checked in the component's story and test (Task 1).
3. A keyboard handler added to a vendored element that steals keys from a focused child or fires twice with an existing handler (Task 2).
4. `schema-table`'s change shows on `apps/docs`'s generated developer reference pages: the region keeps its accessible name, and the committed MDX/drift test stays green (Task 1).
5. The override growing into a catch-all again: only rules a vendored file still breaks after fixes may be listed (Task 2).
