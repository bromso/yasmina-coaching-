# i18n G1 — foundation, API, emails and the auth app — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user can pick Swedish once and get the auth app, the API's messages and every email in
Swedish, remembered across subdomains and devices; English stays byte-identical by default.

**Architecture:** A new `@repo/i18n` package owns the locales, negotiation, the `locale` cookie and
the ICU message catalogs (`messages/<locale>/<namespace>.json`). `apps/api` reads `x-locale`, stores
`users.locale` (migration `0017_user_locale`) and translates its user-facing messages and emails with
`use-intl/core`. `@repo/session` resolves the locale per request (saved preference → cookie →
`Accept-Language` → `en`), sends it as `x-locale`, and offers `setLocale`. `apps/auth` uses
`next-intl` without routing. `@repo/ui` stays free of next-intl: its components take strings as
props, with English defaults.

**Tech Stack:** `next-intl` 4.14.9 and `use-intl` 4.14.9 (new catalog pair), Next 16.2, React 19.2,
Bun 1.4.2, Zod 4, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-08-i18n-design.md` — this plan is **G1**; G2 (`app`,
`account`, the rest of `@repo/ui`, the static apps' switcher) follows after this merges.

## Global Constraints

- Biome clean with zero warnings; double quotes, no semicolons, 2-space indent, 100-char lines.
- Conventional Commits, header ≤ 100 chars, one type per header; every commit message ends with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- New dependencies only `next-intl` and `use-intl`, both `4.14.9`, pinned in the root `catalog`.
- `LOCALES = ["en", "sv"]`, `DEFAULT_LOCALE = "en"`, `LOCALE_COOKIE = "locale"`; the cookie is one
  year, `SameSite=Lax`, `Path=/`, on `COOKIE_DOMAIN`, `Secure` over https, readable by JavaScript.
- Resolution order: saved preference (`users.locale`) → `locale` cookie → `Accept-Language` → `en`.
- English output stays byte-identical: every existing English test, e2e journey and email subject
  passes unchanged.
- No HTML in messages (rich text through `t.rich`); ICU for plurals and selects.
- `@repo/ui` does not depend on next-intl; components take their text as props with English
  defaults.
- The superadmin `/admin` pages stay English and are outside the hard-coded-string guard.
- No new environment variables.

## Review Focus

1. **A Swedish user hits an error the API returns** (wrong password, rate limit, seat limit) — the
   message is Swedish, never an English sentence inside a Swedish page. (Task 2 tests)
2. **An `x-locale` or cookie value that is garbage** (`xx`, `en-US`, empty, 500 chars) — treated as
   unsupported or negotiated (`en-US` → `en`), never stored, never crashes. (Task 1 + Task 2 tests)
3. **A signed-in user whose saved preference differs from the cookie** (they switched on another
   device) — the saved preference wins, and the switcher updates both. (Task 4 + Task 6 tests)
4. **A Swedish validation error from Zod** (bad email, short password) — shown in Swedish, not
   Zod's English default. (Task 5 test)
5. **A message with a plural or a value** (`{count}` attempts, `{email}`) rendered in Swedish —
   correct form, the value substituted, no ICU syntax leaking. (Task 1 parity/ICU test, Task 3 email
   test)

```ts
export const LOCALES = ["en", "sv"] as const
export type Locale = (typeof LOCALES)[number]
export const DEFAULT_LOCALE: Locale = "en"
export const LOCALE_NAMES: Record<Locale, string> // { en: "English", sv: "Svenska" }
export function isLocale(value: unknown): value is Locale
export function negotiateLocale(acceptLanguage: string | null | undefined): Locale // q-weights; "sv-SE" → "sv"; garbage → "en"
export function resolveLocale(input: { saved?: string | null; cookie?: string | null; acceptLanguage?: string | null }): Locale
// ./cookie
export const LOCALE_COOKIE = "locale"
export const LOCALE_MAX_AGE = 31_536_000
export function parseLocaleCookie(cookieHeader: string | null | undefined): Locale | null
export function localeCookie(locale: Locale, options: { domain?: string; secure: boolean }): string // Set-Cookie value, no HttpOnly
// ./messages
export type Namespace = "common" | "ui" | "auth" | "email" | "api"
export type Messages = { [N in Namespace]: (typeof EN)[N] } // EN = the English JSON files imported per namespace; the type next-intl's AppConfig uses
export function messagesFor(locale: Locale, namespaces: readonly Namespace[]): Record<string, unknown> // English merged under the locale (missing keys fall back)
// ./translate (no React, for apps/api and @repo/email)
export function translatorFor<N extends Namespace>(locale: Locale, namespace: N): (key: string, values?: Record<string, string | number | Date>) => string
//   use-intl/core createTranslator; onError: a missing key → the English message, never a raw key; never throws
```
