# Browser End-to-End Tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A deterministic Playwright suite over the cross-app journeys, run against production builds on the real `*.brand.localhost` hosts, gated in CI by the planner.

**Architecture:** `apps/api` gains a `file` mail provider so tests can read one-time links. A new workspace `apps/e2e` holds `@playwright/test`, a config whose `webServer` array starts `api`, `ai`, `www`, `app`, `auth`, `account` in production mode against a throwaway SQLite file, fixtures for mail and accounts, and eight spec files. `scripts/ci-plan.ts` gains an `e2e` output and `ci.yml` an `e2e` job.

**Tech Stack:** Playwright (`@playwright/test` ^1.63, Chromium), Bun 1.3/1.4, Next 16 `next start`, `bun test` for the planner and the mail provider.

**Spec:** `docs/superpowers/specs/2026-10-04-e2e-design.md`

## Global Constraints

- Production mode everywhere (`NODE_ENV=production`), real hosts and ports: www 3000, app 3001, auth 3002, account 3003, api 3007, ai 3008, all on `<name>.brand.localhost`.
- Chromium only; `workers: 1`; `fullyParallel: false`; `retries: process.env.CI ? 1 : 0`; `trace: "retain-on-failure"`; `screenshot: "only-on-failure"`.
- No fixed sleeps (`waitForTimeout` is forbidden); web-first assertions and the mail poller only.
- Selectors by role, label and visible text only; **no test ids added to app code**.
- Every test creates its own users with `uniqueEmail()`; no test depends on another's state; each run starts from an empty `apps/e2e/.tmp`.
- `MAIL_PROVIDER=file` needs `MAIL_DIR` at any `NODE_ENV`; error text exactly `MAIL_PROVIDER=file needs MAIL_DIR`; startup warning in production exactly `⚠ MAIL_PROVIDER=file: emails are written to disk, not sent. Set MAIL_PROVIDER=smtp or resend.`
- Superadmin in e2e: `admin@e2e.test`. Fixed tokens: `API_SERVICE_TOKEN=e2e-api-service-token-0123456789abcdef`, `AI_SERVICE_TOKEN=e2e-ai-service-token-0123456789abcdef` (≥ 32 chars).
- CI job budget `timeout-minutes: 20`; the final `ci` job must treat a skipped `e2e` as passing.
- Code style: Biome (double quotes, no semicolons, 2 spaces, 100 cols). Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **The api's per-email limiters tripping in a serial run** (sign-in 10/15 min per email, magic link 3/15 min per email) — a person expects a green suite on re-run; pinned by `uniqueEmail()` per test (Task 2) and no test signing in more than three times with one address.
2. **`*.brand.localhost` not resolving** (a CI image change, a Linux dev box without systemd-resolved) — a person expects a clear failure, not 120 s timeouts; pinned by the CI host assertion step (Task 5) and a README note (Task 6).
3. **A stale `.tmp` mailbox or database from an aborted run** — the next run must not read an old link; pinned by `global-setup.ts` recreating `.tmp` (Task 2) and `latestMail` taking an `after` timestamp (Task 2 fixture test).
4. **Production `Secure` cookies over http** — sign-in must survive across subdomains; pinned by the auth journey crossing app → account → auth (Task 3).
5. **A server that crashes at boot** (missing env in production) — the run must fail fast with the server's output; pinned by `webServer` `timeout` and `stdout: "pipe"` (Task 2).

```ts
import { mkdir, writeFile } from "node:fs/promises"
import { join } from "node:path"
import type { Mailer } from "./mailer"

/**
 * Writes each message to `<dir>/<ms>-<hex>.json` instead of sending it — for end-to-end tests and
 * local runs that need the links in a mail. Never for production mail: the api warns at startup.
 */
export function fileMailer(dir: string): Mailer {
  return {
    kind: "file",
    async send({ to, subject, text, html }) {
      await mkdir(dir, { recursive: true })
      const name = `${Date.now()}-${crypto.randomUUID().replaceAll("-", "").slice(0, 6)}.json`
      const mail = { to, subject, text, html, sentAt: new Date().toISOString() }
      await writeFile(join(dir, name), JSON.stringify(mail, null, 2))
    },
  }
}
```

`apps/e2e/fixtures/mail.ts`:

```ts
import { readdirSync, readFileSync } from "node:fs"
import { join } from "node:path"
import { MAIL_DIR } from "../e2e.env"

export type Mail = { to: string; subject: string; text: string; html: string; sentAt: string }

/** The newest mail to `to` whose subject matches, sent at or after `after` (ms); polls up to 5 s. */
export async function latestMail(
  to: string,
  subject: RegExp,
  { after = 0, timeoutMs = 5_000 }: { after?: number; timeoutMs?: number } = {}
): Promise<Mail> {
  const deadline = Date.now() + timeoutMs
  for (;;) {
    const found = readdirSync(MAIL_DIR)
      .filter((name) => name.endsWith(".json") && Number(name.split("-")[0]) >= after)
      .sort()
      .map((name) => JSON.parse(readFileSync(join(MAIL_DIR, name), "utf8")) as Mail)
      .filter((mail) => mail.to === to && subject.test(mail.subject))
      .at(-1)
    if (found) return found
    if (Date.now() > deadline) throw new Error(`no mail to ${to} matching ${subject} in ${timeoutMs} ms`)
    await new Promise((resolve) => setTimeout(resolve, 100))
  }
}

/** The first URL in the mail's text body matching `pattern`. */
export function linkIn(mail: Mail, pattern: RegExp): string {
  const url = mail.text.match(/https?:\/\/\S+/g)?.find((u) => pattern.test(u))
  if (!url) throw new Error(`no link matching ${pattern} in "${mail.subject}" to ${mail.to}`)
  return url
}
```

(The 100 ms poll is a filesystem poll, not a UI wait — it is not covered by the no-`waitForTimeout` rule.)

```yaml
  e2e:
    # The Playwright journeys (apps/e2e) against production builds on *.brand.localhost.
    runs-on: ubuntu-latest
    needs: changes
    if: needs.changes.outputs.e2e == 'true'
    timeout-minutes: 20
    steps:
      - uses: actions/checkout@v7

      - uses: oven-sh/setup-bun@v2
        with:
          bun-version: 1.3.14

      - name: Cache Bun dependencies
        uses: actions/cache@v6
        with:
          path: ~/.bun/install/cache
          key: bun-${{ runner.os }}-${{ hashFiles('bun.lock') }}
          restore-keys: |
            bun-${{ runner.os }}-

      - name: Install dependencies
        run: bun install --frozen-lockfile

      - name: Resolve *.brand.localhost to loopback
        run: |
          if ! getent hosts app.brand.localhost | grep -qE '127\.0\.0\.1|::1'; then
            for h in www app auth account docs help jobs api ai; do
              echo "127.0.0.1 $h.brand.localhost" | sudo tee -a /etc/hosts
            done
          fi
          getent hosts app.brand.localhost

      - name: Cache Playwright browsers
        uses: actions/cache@v6
        with:
          path: ~/.cache/ms-playwright
          key: playwright-${{ runner.os }}-${{ hashFiles('bun.lock') }}

      - name: Install Chromium
        run: bunx --cwd apps/e2e playwright install --with-deps chromium

      - name: Build the apps under test
        run: bun run --filter @repo/www --filter @repo/app --filter @repo/auth --filter @repo/account build

      - name: Run the journeys
        env:
          CI: "true"
        run: bun --filter @repo/e2e test:ci

      - name: Upload the report
        if: failure()
        uses: actions/upload-artifact@v5
        with:
          name: playwright-report
          path: |
            apps/e2e/playwright-report
            apps/e2e/test-results
          retention-days: 7
```
