# Webhooks

Full reference; `CLAUDE.md` keeps the summary and the index. A bold name such as **Jobs** refers to its entry there, whose link leads to the sibling file here.

**Webhooks.** Phase 11 B: a workspace admin or owner pushes its own events to URLs it chooses, so an integration reacts without polling `/v1` — same ownership and plan as API keys. Migration `0028_webhooks` adds `webhook_endpoints` (`workspace_id` `ON DELETE CASCADE`, `url` ≤ 2000, `description` ≤ 200 nullable, `events` a JSON array text with at least one, `secret` AES-256-GCM `v1:<iv>:<ct>` under `TWO_FACTOR_ENCRYPTION_KEY` — like TOTP secrets, it must stay readable to sign, so it is encrypted, never hashed — `created_by` nullable with no FK, `created_at`, `enabled`, `consecutive_failures`, `disabled_at`, `disabled_reason` one of `failures`/`gone`/`manual`/null) and `webhook_deliveries` (one row per attempt: `endpoint_id` `ON DELETE CASCADE`, `event_id`, `event_type`, `attempt`, `status` or null, `error` one of `timeout`/`network`/`blocked`/`redirect`/`http`/null — never a body — `duration_ms`). `workspaces.webhooks.{list, create, update, rotateSecret, delete, test, deliveries}` (⚑, `member("admin")`): `create`, `update` (re-enabling included), `rotateSecret` and `test` need the paid `api` feature, checked before the SSRF guard so a Free workspace never triggers a DNS lookup; `list`, `deliveries` and `delete` work on every plan, so a downgraded workspace still manages what it already has; everything but `list`/`deliveries` is refused while impersonating. At most `MAX_WEBHOOK_ENDPOINTS` (10) endpoints per workspace, counted inside the inserting transaction under `workspaces.lockForOwnership`, so two concurrent creates at 9 cannot both land a 10th (`CONFLICT` `WEBHOOK_LIMIT_MESSAGE`). A URL must be `https`, carry no userinfo and no `#fragment`, at most 2000 characters, and resolve — at creation and on a URL change — to only public addresses; with `WEBHOOK_ALLOW_LOCALHOST_HTTP` (any `NODE_ENV`, see below) `http`/`https` to `localhost`/`*.localhost` is let through too, pinned to `127.0.0.1` with no DNS lookup. **The secret:** `whsec_` + base64 of 32 random bytes (`newWebhookSecret`), shown exactly once by `create` and `rotateSecret` and otherwise unreadable even to us; **Rotate secret** replaces it at once, with no overlap window — the very next attempt signs with the new one, retries of events queued before the rotation included. **The SSRF guard** (`apps/api/src/webhooks/ssrf.ts`, OWASP's SSRF Prevention Cheat Sheet): refuses a URL unless every A/AAAA record its host resolves to (or, for an IP literal, the literal itself) is public — loopback, RFC 1918, link-local, CGNAT, the metadata/documentation/benchmarking/6to4-relay ranges, multicast and reserved space all refused, with IPv4-mapped/compatible/translated/6to4 IPv6 forms judged by the IPv4 address they carry and NAT64 (`64:ff9b::/96`, `64:ff9b:1::/48`) refused outright. It runs again at delivery time, immediately before dialling, so DNS rebinding between create/update and send is never a way in: only the addresses that check just returned are ever dialled, with the checked address written into fetch's own URL and the real hostname sent only as `Host` (and, over https, `tls.serverName` for SNI and the certificate check), `redirect: "manual"` (a 3xx is recorded, never followed), one 10-second deadline for the whole attempt (every address tried; the DNS lookup before it has its own 5-second bound), and the response body cancelled unread — never stored, logged or forwarded. **Signing** follows Standard Webhooks: `webhook-id` (`msg_…`), `webhook-timestamp` (unix seconds) and `webhook-signature: v1,<base64 HMAC-SHA256(key, "id.timestamp.body")>` over the exact bytes sent, `key` the base64-decoded secret after `whsec_`; `standardwebhooks`, the official library, is an `apps/api` devDependency only, proving our signature verifies exactly as a receiver's would — never a runtime dependency. **Events:** `note.created`, `note.deleted`, `member.joined`, `member.left`, `member.role_changed`, `workspace.updated`, `api_key.created`, `api_key.revoked`, plus a test-only `ping` from **Send test event**. Each delivery's body is `{ type, timestamp, data }`, minified JSON; `data` is the same object `/v1` returns for that resource — `note.created` a `Note`, `note.deleted` `{id}`, `member.*` `{userId, name, role, joinedAt}` (+ `previousRole` on `role_changed`), `workspace.updated` `{id, name, slug, plan}`, `api_key.*` `{id, name, prefix, scopes, expiresAt}`, `ping` `{endpointId}` — never an email address — schemas in `@repo/public-api-contract/webhooks`, additive-only like `/v1`. **Emitters:** `emitWebhookEvent(ctx, workspaceId, type, data, { tx? })` is called where the change already happens — notes create/delete (internal and `/v1`), member join (invitation accept), leave/remove, role change, workspace rename and logo, API key create/revoke — inside the change's own transaction, so a rolled-back change sends nothing and a committed one sends exactly once; `privacy.purge` emits `member.left` with `name: ""` for every membership it is about to remove, since the account is being erased by the same transaction. One event id and timestamp per event, one `webhook.deliver` job per enabled, subscribed endpoint of a workspace that still has the `api` feature (checked once per emit, and again by the job). **The delivery job** (`maxAttempts` 8, `timeoutMs` 30 s): re-loads the endpoint first — gone, disabled, unsubscribed or feature-lost finishes quietly — reruns the SSRF guard, decrypts the secret and signs with the attempt's own timestamp. A 2xx resets the failure count; `410 Gone` disables the endpoint at once (`gone`, no retry); anything else throws so the queue retries with its usual backoff (30 s doubling each retry, about an hour spread across the 7 retries before the 8th and last attempt). Every attempt writes one `webhook_deliveries` row. When the last attempt dies, `consecutive_failures` increments; at `WEBHOOK_MAX_CONSECUTIVE_FAILURES` (5) the endpoint is disabled (`failures`), audited (`workspace.webhook_disabled`, actor null, metadata without the secret) and every owner mailed `webhookDisabled` (en + sv, saved locale) naming the host and why — never the path or query. A final attempt lost outright (the worker crashing mid-run, or its bookkeeping cut off) is not counted toward the five; a worker timeout still is, since the run continues and records `timeout`; an admin's **Retry** on the dead job runs 8 more attempts and can count again. `webhooks.prune` (`55 3 * * *`) deletes delivery rows older than 30 days (indexed on `created_at`). **Capacity:** an endpoint that drops packets holds a worker slot for its whole attempt, so a process runs at most `WEBHOOK_CONCURRENCY` (default 2, 1 to `JOBS_CONCURRENCY`) `webhook.deliver` jobs at once — the worker's per-name caps (`nameLimits`) claim them separately from every other job, so mail and the rest keep their slots — and `test` is limited to `WEBHOOK_TEST_RATE_LIMIT` (20) per workspace per hour (`webhook-test:<workspaceId>`, in memory, `TOO_MANY_REQUESTS` `WEBHOOK_TEST_RATE_MESSAGE`); the cost is webhook throughput, at most that many attempts in flight per process. **The proxy caveat:** Bun 1.4.2 ignores fetch's `proxy: false` — with `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` set, a delivery still goes through that proxy, asked for the checked address already in the URL (so the SSRF pinning holds, but the proxy sees every delivery); the api and the worker log one startup warning naming the variable. `WEBHOOK_ALLOW_LOCALHOST_HTTP` (default false) is the only way to allow delivery to `localhost`/`*.localhost`, in any `NODE_ENV` — a loud warning when it is on in production ("never in a real deployment"); `apps/e2e` sets it, and plain `bun dev` needs it set to reach a `*.localhost` receiver. **The UI:** `apps/account`'s Workspace page gets a **Webhooks** card below API keys, gated the same way — below admin a read-only note; admin/owner on Free the list with **Recent deliveries** and **Delete** only (an upsell in place of **Add endpoint**); on Pro/Team the full card: add (URL, description, event checkboxes, none ticked) → a show-once secret panel, per-row **Edit** (URL/description/events/enabled in one submit), **Rotate secret** (two-click, like Delete, then show-once), **Send test event**, **Recent deliveries**, two-step **Delete** — read-only while impersonating, works with no JavaScript except copy-to-clipboard. Basis: Standard Webhooks (the headers, the 5-minute tolerance, dedup on `webhook-id`), OWASP's SSRF Prevention Cheat Sheet (resolve and check every address, re-check at delivery, never follow a redirect) and GDPR Art. 25(2)/28 (no emails, no preselected events, the endpoint's operator as the workspace's own recipient or processor). See `apps/api/README.md`, `apps/account/README.md`, `packages/public-api-contract/README.md`, `packages/email/README.md` and `docs/guides/webhooks.md`.
