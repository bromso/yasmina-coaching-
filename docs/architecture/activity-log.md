# Activity log

Full reference; `CLAUDE.md` keeps the summary and the index. A bold name such as **Jobs** refers to its entry there, whose link leads to the sibling file here.

**Activity log.** Phase 12 A: a workspace's own admins and owners can see who changed what in their workspace, without asking the platform's support. Migration `0029_audit_workspace` adds a nullable `audit_log.workspace_id` (no FK, so a row outlives its workspace, as one outlives a purged actor through `actor_user_id`'s `ON DELETE SET NULL`) and an index `audit_log_workspace (workspace_id, at)`; no backfill, so the log starts empty at deploy — before this column only impersonation-time rows named a workspace at all. `auditWorkspace(context, workspaceId, input, client?)` in `apps/api/src/admin.ts` is the write path for every action `WORKSPACE_ACTIVITY_ACTIONS` names (`@repo/api-contract`, 21 actions, including `workspace.ownership_transferred`, `workspace.plan_changed`, from Phase 12 B `workspace.two_factor_requirement_changed` — see **Required two-step.** — and, from Phase 12 C, `workspace.invite_domains_changed` — see **Invitation domains.**): unlike `auditWhileImpersonating`, it always records, inside the change's own transaction wherever there is one, and only on a real change — a same-name rename, a same-role `setRole` or an accept by someone already a member records nothing. The actor is the session user, or the impersonator with the user recorded as `impersonated` exactly as `audit()` does; with no user and an API key (no `/v1` route writes one yet, but the path supports it), the actor is null and `metadata.apiKeyId`/`apiKeyName` name the key; with neither, the actor is null — the system, for a Stripe webhook's plan change or the delivery job's auto-disable. An impersonated row also carries `metadata.bySupport: true`, so a later purge (which nulls `impersonated_user_id` but keeps the superadmin as `actor_user_id`) can never re-attribute the superadmin as the member who acted. Targets moved from the workspace itself to what was actually changed — `user` (member actions and `invitation.accepted`), `invitation` (`invitation.created` and `invitation.revoked`), `api_key`, `webhook` — which is why the audit export and superadmin filter above now also match `workspace_id` (see **Audit retention and export**). `invitation.created` and `invitation.revoked` store the invitee's address masked (`maskEmail`), never in full.

`workspaces.activity.list({ workspaceId, cursor?, limit?, action? })` (⚑, `member("admin")`, every plan, readable while impersonating since it writes nothing) reads the log back — `apps/api/src/workspace-activity.ts` and `queries/audit.ts`'s `listForWorkspace`: rows at or after `now − WORKSPACE_ACTIVITY_DAYS` (90, from `Context.now()`), keyset-paged on `(at, id)` descending toward older entries only, with an optional `action` filter over the same action enum. Each item's `actor` is one of four kinds (`WORKSPACE_ACTIVITY_ACTOR_KINDS`): `member` (name always; email only while that person is a *current* member of the workspace — a former member keeps their current name, never their address, the same data-minimisation the rest of the product applies), `apiKey`, `system` (only for `workspace.plan_changed` and `workspace.webhook_disabled` — any other actor-less row belonged to an account since purged) or `deleted`. `target` is the member's current name, a key's name or an endpoint's host; `details` is the action's own display allowlist (`ACTIVITY_DETAILS`) — never `ip`, `user_agent`, `reason`, or any staff id. The data export's metadata allowlist (`EXPORTED_AUDIT_METADATA` in `jobs/builtin/privacy.ts`) was widened the same way, and its inline `"you"`/`"admin"` label is now `exportedAuditBy`, with a third value, `"workspace"` (another member, one of the workspace's own API keys, or the system, acting on the exported user — never platform staff).

`apps/account`'s `/workspace` page gets an **Activity** card below Webhooks, admin and up (absent below that, every plan — a safety feature, not an upsell): a type filter and **Older**/**Newest** paging links, all plain GET forms and links, so the whole card works with no JavaScript. Basis (checked 2026-10-19): OWASP's Logging Cheat Sheet (record "when, where, who and what"; mask what the purpose does not need; restrict and review who may read log data) and Garante/CNIL employee-monitoring decisions on transparency to the people monitored and proportionality of what is recorded — hence admin-and-up only, 90 days, no ip or user agent ever shown, and the legal app's privacy page (`apps/legal`) says so. See `apps/api/README.md` and `apps/account/README.md`.
