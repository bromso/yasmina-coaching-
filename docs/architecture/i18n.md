# i18n

Full reference; `CLAUDE.md` keeps the summary and the index. A bold name such as **Jobs** refers to its entry there, whose link leads to the sibling file here.

**i18n.** Phase 7's last sub-project, delivered as two PRs (G1 then G2; both merged — English and
Swedish everywhere the product shows text). `packages/i18n` (`@repo/i18n`) is the shared,
framework-free layer: `LOCALES = ["en", "sv"]`, `DEFAULT_LOCALE = "en"`, `LOCALE_NAMES` (each
language's own name, for a switcher), `negotiateLocale` (`Accept-Language`, honouring quality
weights, `sv-SE` → `sv`), static ICU catalogs at `messages/<locale>/<namespace>.json` for `common`,
`ui`, `auth`, `email`, `api`, `app` and `account` (seven namespaces), `messagesFor` (English merged
in under the locale, so a half-translated catalog never shows a raw key) and `translatorFor`
(`use-intl/core`, for callers with no React — `apps/api` and `@repo/email` — that never throws).
**Resolution, per request**: a signed-in user's saved preference (`users.locale`, migration
`0017_user_locale`, nullable — `null` reads as English; `Me.localeChosen` tells "chose English"
apart from "never chose", since the column alone cannot), else the `locale` cookie (one year,
`SameSite=Lax`, `Path=/`, on `COOKIE_DOMAIN`, `Secure` in production, readable by JavaScript —
unlike the session cookie, since a static app's switcher must write it from the browser), else
`Accept-Language`, else `en`. `@repo/session`'s `getLocale()`/`setLocale()` implement this for
every Next app (see its README): the resolved `{ locale, source }` is cached once per request in
its own map, apart from the `auth.me` memo behind `getMe()` — a profile write drops `Me` so the
next read is fresh, but never the locale, since no profile write can change it; `setLocale`
overwrites the cached entry with the value it just saved, and `invalidateMe()` clears both. Every
`createAuth` client sends the resolved locale as `x-locale` on each api call (`anonymousApi()`
omits it when nothing but the English fallback applies, so a sign-up gets no locale rather than a
guessed one), except `auth.me` itself and the `*FromRequest` helpers (`getUserFromRequest`,
`getMeFromRequest`, `resolveWorkspaceFromRequest`), which send the request's own cookie /
`Accept-Language` locale via the exported `localeFromRequest(req)`, not the resolved one (resolving
needs `auth.me`'s answer). The api reads `x-locale` into `Context.locale` (`apps/api/src/i18n.ts`)
and answers every user-facing message through `apiMessage(context, key, values?)` — never a
literal string in a handler; a test pins every catalog key with a named `@repo/api-contract`
constant to equal that constant in English, so the catalog and the contract's declared defaults
can never drift apart, and admin-only messages stay English on purpose. `account.setLocale` (⚑)
saves the preference, audited while impersonating like a profile write. `@repo/email`'s ten
templates take `locale` as their second argument (default `"en"`); English stays byte-for-byte
identical to before i18n (a committed snapshot fixture proves it), and `apps/api` picks the locale
per mail: the account's own saved locale (English when it never chose one) for the mails it
receives without asking — `passwordChanged`, `twoFactorEnabled`/`twoFactorDisabled`,
`accountReset`, `twoFactorReset`; for the mails the user asked for themselves — `resetPassword`,
`magicLink`, `verifyEmail` (sign-up and resend) — the saved locale when chosen, else the locale the
request named (`Context.requestedLocale`), else English, which also covers a magic link to an
address with no account yet; an `invitation` uses the invitee's saved locale when the address
already has an account that chose one, else the inviter's request locale; `waitlistWelcome` the
anonymous caller's request locale.

`apps/auth`, `apps/app` and `apps/account` are fully translated: `next-intl` without routing
(`src/i18n/request.ts`, no `[locale]` segment, `getLocale()` resolves it, `connection()` plus
`unstable_rethrow(error)` so it never runs while a build prerenders and never logs a locale
resolution failure at build time), the header's `LocaleSwitcher` (`@repo/ui`, a select plus an
always-visible submit button, applied only on submit — with or without JavaScript) posting to a
`setLocale` server action, and `/admin/**` excluded on purpose (internal tooling). `apps/account`
additionally has a **Language** card on Personal info (`LanguageForm` over `setLocaleCore`): a
`useActionState` form like every other settings card, so a refusal or the confirmation shows
in place rather than as a redirect, and success re-renders the whole page (`revalidatePath("/",
"layout")`) in the new language. `@repo/ui` still takes no `next-intl` dependency, but does depend
on `@repo/i18n` — only its client-safe `./cookie` and `./locales` subpaths, for
`StaticLocaleSwitcher` below. `SidebarProvider`/`SidebarTrigger`/`SidebarRail` take `labels`
(`toggle`, `open`, `close`, `title`, `description`; memoized on the individual strings, not the
object, so a render-phase update with the same strings is a no-op; the mobile sheet's close button
reads `close` too), `SiteHeader`/`SiteFooter` take `navLabel` (the header's mobile sheet uses the
same one) and `SiteHeader` takes `mobileLabels` (`open`, `title`, `close`; `SheetContent` takes a
`closeLabel`), the cross-app links and footer group titles are relabelled by id through
`relabelNav`/`relabelFooter` from `@repo/sites` (`ui.sites.<id>`, `ui.footerGroups.<id>`; the
static apps keep the English labels), and `LocaleSwitcher` takes `selectProps` (a field error's `aria-invalid` /
`aria-describedby`) and `pending`; `CookieConsent`, `SkipLink`, `ThemeToggle`, `SignInLink`,
`UserMenu` and `ImpersonationBanner` keep the label props from G1. Every prop defaults to today's
exact English string, so an app that passes none is unaffected. A Zod issue is mapped to a
translated message by its `code` (and a custom refine's `params.key`), never by its English text,
at the action boundary (`zodMessage(t)` in each app's own `src/lib/i18n.ts`, fed to `@repo/ui`'s
`fieldErrors`).

Each translated app runs its own hard-coded-string guard as a test
(`src/i18n-guard.test.ts`, over `packages/i18n-guard`'s `scanApp` — a workspace package rather
than a file under `scripts/`, because it needs `typescript` (catalogued; see the dependency rules
above) and CI's planner job runs `bun test scripts` before `bun install`). `scanApp` parses every
`.tsx` under the app's `src/` with the TypeScript compiler (outside admin pages, tests and
`global-error.tsx`) and flags `JsxText` with a letter, a string or template literal written as a
JSX child (either branch of a conditional and `&&`/`||`/`??` operands included, through
parentheses), and a literal value, plain or in braces, of `placeholder`, `aria-label`, `alt`,
`title`, `label` or `aria-description`; HTML entities are decoded first, so a decorative
`&nbsp;`/`&middot;`/… is not text while an unknown or misspelled one still is. It cannot see a
string built or held in a variable outside the JSX, other attributes or props, or text a `.ts` file
renders — a floor, not a guarantee. Each app's own `i18n-guard.allowlist.json` (matched by file and
text, each entry carrying a reason) takes a genuine false positive; all three are empty today.

The static apps (`www`, `docs`, `help`, `jobs`, `blog`) stay static and stay English: each gets
`StaticLocaleSwitcher` (`@repo/ui/components/static-locale-switcher`) in the header's `controls` slot,
passing the app's existing build-time `cookieDomain`. Until hydrated it renders only an invisible,
`aria-hidden`, `inert` placeholder of the same size (a static page has no per-request render to
post a form to, and the header must not shift when the real switcher appears), then reads the
`locale` cookie client-side; on pick it writes that cookie itself (`writeLocaleCookie`, mirroring
`CookieConsent`'s own `document.cookie` write) and shows a visible "Saved — signed-in pages will
use it." note in a polite live region, which stays until the page is reloaded — the page itself
never changes language. `apps/www`'s waitlist
action resolves and sends `x-locale` the same way `anonymousApi()` does, from a real signal only
(`resolveWaitlistLocale` over the `locale` cookie and `Accept-Language`, in
`apps/www/src/lib/actions.ts`, since the action builds its own client rather than a `createAuth`
one). Three routes still send no `x-locale` at all, and need none: `createFileRoute`,
`createEventsRoute` and `@repo/telemetry`'s server route each answer with a bodyless status or a
`204`, so nothing they return is ever shown to a person. See `docs/guides/i18n.md`,
`packages/i18n/README.md`, `packages/i18n-guard/README.md`, `packages/session/README.md`'s Locale
section, `apps/api/README.md`'s Locale section, `packages/email/README.md`, `apps/auth/README.md`,
`apps/app/README.md`, `apps/account/README.md` and `apps/www/README.md`.
