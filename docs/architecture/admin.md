# Admin

Full reference; `CLAUDE.md` keeps the summary and the index. A bold name such as **Jobs** refers to its entry there, whose link leads to the sibling file here.

**Admin.** `SUPERADMIN_EMAILS` (api; optional, comma-separated) names the platform admins: an address is a superadmin once its email is verified — computed per request, no column, no seeding, removing it revokes at the next request. `User.superadmin` and `Me.impersonation` come back from `auth.me`. The admin UI is `apps/auth` `/admin` (metrics, users with search and detail, workspaces, audit log); every `admin.*` procedure and every page answers `NOT_FOUND` / 404 to anyone else, impersonation sessions included. **Impersonate** (reason 3–200 chars, limiter `impersonate:<adminId>` 10/h, never yourself or another superadmin, one live impersonation per admin) issues a 60-minute session row with `impersonated_by` + `reason` that `auth.me` never touches; `@repo/session`'s `startImpersonation` parks the admin's token in the host-only `admin_session` cookie (`Path=/admin`, 1 h) and puts the impersonation token in `session`, so the app and account apps simply see the user — with the amber `ImpersonationBanner` and **Stop impersonating** → `${AUTH_URL}/admin/stop`, which calls `admin.stopImpersonation` with the impersonation token and restores the admin (or signs the browser out when the parked token is gone). The api enforces the limits from the session row: `account.changePassword/setPassword/sessions.revoke/sessions.revokeOthers/identities.disconnect/resendVerification`, `account.twoFactor.setup/enable/disable/regenerateRecoveryCodes`, `account.passkeys.registerOptions/register/rename/delete` (`account.passkeys.list` stays readable), `billing.checkout/portal/mockChange`, `workspaces.delete/transferOwnership` answer `FORBIDDEN` "Not available while impersonating"; notes, profile, avatar and logo writes are allowed and each writes an `audit_log` row only while impersonating (`auditWhileImpersonating`; migration `0011_admin`; actor = the admin, impersonated = the user, ip/UA when known); workspace, member, invitation, API key and webhook writes are allowed and always write one, impersonating or not (`auditWorkspace`, with `workspace_id` set — see **Activity log.**) — as do every impersonation start/replace/stop, `admin.users.revokeSessions`, `admin.users.resetTwoFactor`, `admin.users.removePasskeys`, `admin.users.suspend` and `admin.users.unsuspend` (see **Suspension**). Audit is append-only, with bounded retention and a synchronous export — see **Audit retention and export** below.
