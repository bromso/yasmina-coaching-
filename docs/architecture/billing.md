# Billing

Full reference; `CLAUDE.md` keeps the summary and the index. A bold name such as **Jobs** refers to its entry there, whose link leads to the sibling file here.

**Billing.** Billing belongs to the workspace, never the user. The vocabulary lives in `packages/api-contract/src/billing.ts`: `PLANS` (`free` 3 seats, `pro` 10 seats, `team` unlimited; prices in USD cents, display only), `FEATURES = ["chat", "api"]` (the second gates workspace API keys and `/v1` — see **API keys and /v1.**), `BILLING_STATUSES` (Stripe's, verbatim) and `entitlementsFor`, the one rule from a mirrored subscription to what a workspace may do (`active` / `trialing` / `past_due` keep the paid plan, anything else or no subscription is Free), with `hasFeature`, `seatsLeft`, `SEAT_LIMIT_MESSAGE` and `FEATURE_MESSAGES`; `apps/api`, `apps/account`'s Payments page and `apps/www`'s pricing all read `PLANS`. `apps/api` talks to a provider through one seam, `apps/api/src/billing/` (`BillingProvider`: `createCheckout`, `createPortal`, `hasPrice`, `cancelSubscription`, `verifyWebhook`), picked at boot by `BILLING_PROVIDER`: `mock` (the default; keyless, "checkout" activates the plan at once and the Payments page offers an in-app switch/cancel form; with `NODE_ENV=production` the api warns at startup that plans activate without payment) or `stripe` (the `stripe` SDK, confined to `src/billing/stripe.ts`; hosted Checkout and Customer Portal), which needs all six `STRIPE_*` vars or the api exits at startup naming the missing ones. Prices come only from the env (`STRIPE_PRICE_*`): a subscription on any other price is not mirrored. Migration `0010_billing` holds the mirror: `billing_customers` (one provider customer per workspace), `billing_subscriptions` (the state the webhooks reported, with `source_updated_at`) and `billing_events` (the id of every verified event received, applied or not); the mock writes through the same mirror. Entitlements are computed from it on every request, never cached and never fetched from Stripe: `workspaces.list` / `get` carry them as `entitlements`, and `billing.get` adds `provider`. The webhook is `POST /billing/webhook` on `Bun.serve`, outside the bearer guard and the rate limiter by design (Stripe sends neither a token nor a client id): the `Stripe-Signature` over the raw body is the authentication (`400` when missing or bad), the event id is recorded in `billing_events` in the same transaction as the writes (a redelivery is `duplicate`), and an event older than the row's `source_updated_at` is `stale` and changes nothing. Anything it will never apply answers `200` so Stripe stops retrying (`ignored`, `duplicate`, `unattributed`, `conflict`, `gone`, `stale`, `customer_changed`, `unknown_price`); a database failure answers `500` so it retries. Where entitlements bite: `workspaces.invitations.create` and `invitations.accept` / `acceptById` refuse a new member past the plan's seats (`FORBIDDEN` `SEAT_LIMIT_MESSAGE`; members count, pending invitations do not, and an accept refused for seats leaves the invitation pending), and `chat` is a paid feature — `apps/app`'s `/chat` page shows an upsell (`hasFeature(entitlements, "chat")` on `requireWorkspace()`), and its `/api/chat` route answers `403` "Upgrade to use chat" through `resolveWorkspaceFromRequest(req)`, the gate that counts (`503` when the api cannot be asked) — a workspace that also requires two-step verification refuses an unsatisfying caller first, `403` with that message instead, checked before the plan (see **Required two-step.**). `billing.get` is viewer and up; `billing.checkout`, `billing.portal` and `billing.mockChange` are owner only; `workspaces.delete` cancels a live subscription with the provider first and deletes nothing if that fails. Checkout and portal return to URLs the api builds from `ACCOUNT_URL` (`/payments?checkout=success|cancelled`, `/payments`). `apps/account`'s `src/proxy.ts` is the one app proxy with a `csp` extra: `form-action` for `https://checkout.stripe.com` and `https://billing.stripe.com`, so a plain form post may redirect there. Setting up Stripe — products and prices, the webhook endpoint and its four events, the Customer Portal, `stripe listen` locally — is in `docs/guides/stripe.md`. See `apps/api/README.md`, `packages/session/README.md`, `apps/account/README.md` and `apps/app/README.md`.
