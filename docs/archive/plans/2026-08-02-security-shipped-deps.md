# Patch the Shipped Dependencies Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clear 33 of the repository's 86 security advisories by raising `next`, `sharp` and `postcss` above their advisory ceilings, then consolidate all three behind the workspace catalog. (Originally targeted 37 — see the Only `next` can be fully cleared constraint below for why 4 of the 37 cannot be reached from this repo's manifests.)

**Architecture:** Two separable changes. First raise the declared version floors in place so each range provably excludes every vulnerable version — that is the security fix, and it stands alone. Then move `sharp` and `postcss` into the root `catalog`, a pure refactor whose defining property is that it must resolve to identical versions.

**Tech Stack:** Bun workspaces, the Bun `catalog:` protocol, `bun audit`, Biome 2.3.8.

## Global Constraints

- **No source file may change.** This project edits `package.json` manifests and `bun.lock` only. Any `.ts`, `.tsx`, `.css` or config-file change is out of scope.
- Version floors must **exclude** every vulnerable version, not merely permit a fixed one. `next` is vulnerable today despite a caret that already allows the fix.
- Advisory ceilings: `next` `>=16.0.0 <16.2.5`; `sharp` `<0.35.0`; `postcss` `<8.5.10`.
- **Only `next` can be fully cleared.** `next@16.2.12` itself pins `postcss` to an exact `8.4.31` (a pin no range can satisfy differently) and declares `sharp: ^0.34.5` as an optional dependency (a `0.x` caret that cannot reach `0.35.x`). Those two nested copies stay vulnerable and no manifest edit here can reach them. `@tailwindcss/postcss`'s `postcss: ^8.4.41` and `vite@6.4.1`'s `postcss: ^8.5.3` are **not** part of that problem — `8.5.25` satisfies both ranges, so their stale nested `8.5.6` copies are lockfile inertia, reachable by an ordinary dedupe, not a constraint; removing them wouldn't change the audit total since `next`'s exact pin keeps the three `postcss` advisories listed regardless. Raising this repo's own floors is still worth doing — it stops our declarations regressing — but the audit will still list `sharp` and `postcss` when this project is done. Expect 86 → **53**, not 49.
- **The residual `sharp` copy ships to production, and is the most consequential open risk.** Both `apps/app` and `apps/www` build with `output: "standalone"`, and both standalone bundles include the vulnerable `sharp@0.34.5` that arrives via `next`'s own optional dependency (`apps/www` doesn't declare `sharp` at all — it only gets this copy through `next`). `apps/app` serves remote images through `next/image` with `images.remotePatterns` for `images.unsplash.com` and `images.pexels.com`. The advisory, `GHSA-f88m-g3jw-g9cj`, is inherited libvips CVEs in image decoding — exactly the `/_next/image` request-time transcode path. This bump only reaches the `devDependency` copies; it cannot touch the one `next` bundles internally. Do not frame this as deferred build tooling — it is the one thing left that actually executes in production.
- Target floors: `next` `^16.2.12`; `sharp` `^0.35.3`; `postcss` `^8.5.25`.
- Do **not** bump `mathjs` or `style-dictionary`. Both are major bumps on code that never ships and are a separate project.
- Do **not** bump anything under `@repo/story`. The 3 critical advisories live there; that tooling runs the 1228-test suite this plan relies on for evidence.
- Do **not** add entries to the root `overrides` block. The 7 transitive-only advisories are out of scope.
- Biome must be **2.3.8**. Always pass `--max-diagnostics=none`, and `--colors=off` when grepping.
- Biome prints **no** `Found N errors.` line at zero. `grep -E "^Found"` does **not** prove zero errors — `Found 62 warnings.` also matches. Use `grep -E "^Found [0-9]+ errors"`.
- The repo's Husky `pre-commit` hook runs `lint-staged` → `biome format --write` on `*.json`, which will reformat `package.json`. Verify the committed result matches what you staged. `HUSKY=0` bypasses the hook.
- Branch: `fix/security-shipped-deps`, already created from `main` at `336cebf`.

- [ ] **Step 6: Verify the resolutions cleared every ceiling**

```bash
python3 -c "
import re
s=open('bun.lock').read()
ceil={'next':(16,2,5),'sharp':(0,35,0),'postcss':(8,5,10)}
ok=True
for p,c in ceil.items():
    vs=sorted(set(re.findall(rf'\"{p}@([0-9][^\"]*)\"', s)))
    for v in vs:
        t=tuple(int(x) for x in re.findall(r'[0-9]+', v)[:3])
        good = t >= c
        ok &= good
        print(f'  {p}@{v}: {\"OK\" if good else \"STILL VULNERABLE\"} (needs >= {\".\".join(map(str,c))})')
print('ALL CLEAR' if ok else 'FAILED')
"
```

Expected: `next@16.2.12` OK. **`sharp@0.34.5` and `postcss@8.4.31` / `postcss@8.5.6` will report
`STILL VULNERABLE`, and that is the correct result.** The script will print `FAILED`.

This was discovered during implementation and the plan originally expected `ALL CLEAR`, which was
wrong. `next@16.2.12` — the fixed version — hard-pins `postcss: "8.4.31"` as an **exact** dependency
and declares `sharp: "^0.34.5"` as an **optionalDependency**. Neither is reachable by editing this
repo's manifests.

`@tailwindcss/postcss`'s nested `postcss@8.5.6` is a different case and easy to misattribute: it
declares `postcss: ^8.4.41`, and `8.5.25` (this repo's new floor) already satisfies that range, so
the range isn't forcing anything. The stale `8.5.6` is lockfile inertia — bun kept a pre-existing
resolution — and an ordinary dedupe would clear it with no `overrides` needed. It still shows up in
the version set below because this task doesn't force a dedupe, not because it's unreachable.

The expected version sets after this task are exactly:

```
next:    ['16.2.12']
sharp:   ['0.34.5', '0.35.3']            # 0.34.5 is next's optional dependency
postcss: ['8.4.31', '8.5.25', '8.5.6']   # 8.4.31 is next's exact pin; 8.5.6 is @tailwindcss/postcss
```

Anything outside those sets is a genuine failure — stop and report.
