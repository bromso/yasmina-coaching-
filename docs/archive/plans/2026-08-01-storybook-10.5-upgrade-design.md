# Upgrade Storybook to 10.5.5 and remove Chromatic

**Date:** 2026-08-01
**Status:** Approved, ready for implementation planning

## Summary

Move `@repo/story` from Storybook `^10.1.8` to `^10.5.5`, and remove the Chromatic addon, which is
declared but never used.

The upgrade is small in diff terms and almost entirely about verification. `@repo/story` runs 1228
browser-mode Vitest tests through Playwright Chromium on a setup that was only just stabilised, so
the risk is not "does it install" but "does the test harness still behave identically".

## Dropped from the original request

The request also asked to install [termcn](https://github.com/shadcn-labs/termcn) via
`bunx --bun shadcn add @termcn/ink/app-shell` and add stories for its components. That is not
possible as stated, and was dropped after discussion.

termcn renders React to a **terminal**, built on [Ink](https://github.com/vadimdemedes/ink) and
[OpenTUI](https://opentui.com/) — the latter being TypeScript over a native Zig core emitting ANSI
escape codes. Storybook renders in a **browser**. An Ink/OpenTUI tree produces no DOM, so it cannot
render in a Storybook story. There is no official termcn Storybook; the only bridging precedent is
[ink-storybook](https://github.com/skorfmann/ink-storybook), an unofficial project that pipes Ink
through xterm.js.

Three repo-specific facts reinforced this:

- No workspace in this monorepo runs in a terminal. `apps/` is `app`, `www` and `story`, all browser
  targets.
- `packages/ui` is a DOM component package (`react-dom`, consumed by two Next.js apps). Ink
  components do not belong there.
- The given command would fail regardless: `packages/ui/components.json` registers `@react-bits`,
  `@animate-ui` and `@magicui`, with no `@termcn` entry.

If terminal UI work is wanted later, it needs its own workspace and its own spec.

## Verified compatibility

All measured against the installed versions, not assumed.

| Package | Repo has | 10.5.5 requires | Status |
|---|---|---|---|
| `vitest` | `^4.0.15` | `^3.0.0 \|\| ^4.0.0` | satisfied |
| `@vitest/browser-playwright` | `^4.0.15` | `^4.0.0` | satisfied |
| `vite` | `^6.3.5` | `^5 \|\| ^6 \|\| ^7 \|\| ^8` | satisfied |
| `react` / `react-dom` | 19 | `^16.8 \|\| ^17 \|\| ^18 \|\| ^19` | satisfied |
| `typescript` | `^5.9.2` | `>= 4.9` | satisfied |
| `@chromatic-com/storybook` | `^4.1.3` | peers cap at `^10.3.0-0` | **incompatible** |

Nothing beneath Storybook needs to move. That matters for `playwright@1.57.0` in particular, which
is pinned deliberately: CI installs browsers with `working-directory: apps/story` so the installed
build number matches the one Vitest launches. An unforced Playwright bump would break that.

`@chromatic-com/storybook@4.1.3` is the single forced change — its peer range stops at Storybook
10.3, so it cannot stay as-is.

## Design

### 1. Version bumps

In `apps/story/package.json`, set all seven to `^10.5.5`:

- `storybook`
- `@storybook/react-vite`
- `@storybook/addon-a11y`
- `@storybook/addon-docs`
- `@storybook/addon-links`
- `@storybook/addon-themes`
- `@storybook/addon-vitest`

These release in lockstep; mixing versions across them is unsupported.

**Method: manual edits, then `bun install`.** Not `storybook upgrade`. The CLI rewrites config in
place, and both `.storybook/main.ts` and `apps/story/vite.config.ts` carry deliberate
customisations — the Tailwind v4 Vite plugin, `reactDocgen: "react-docgen"`, `chunkSizeWarningLimit`,
browser-mode instances, and `retry: 2`. A hand-reviewable diff is worth more here than
automigration coverage.

### 2. Remove Chromatic

Five touchpoints, all in `@repo/story`:

| Location | Change |
|---|---|
| `apps/story/package.json` devDependencies | delete `"@chromatic-com/storybook": "^4.1.3"` |
| `apps/story/package.json` devDependencies | delete `"chromatic": "^13.3.4"` |
| `apps/story/package.json` scripts | delete `"visual-test": "chromatic"` |
| `apps/story/.storybook/main.ts` addons array | delete `"@chromatic-com/storybook"` |
| `apps/story/chromatic.config.json` | delete the file |

This is removal, not disabling. Chromatic is not wired up anywhere: no workflow references it and no
`CHROMATIC_PROJECT_TOKEN` secret is used. Bumping an unused addon across a major version would mean
shipping an untested upgrade of something providing no current value.

> **Corrected during implementation.** This section originally claimed no `chromatic.config.json`
> exists, and listed four touchpoints rather than five. That was wrong:
> `apps/story/chromatic.config.json` has been tracked since the initial commit and contains
> `{"buildScriptName": "build", "zip": true}`. The claim came from a shell command whose glob failed
> and aborted before `ls` ran, so empty output was misread as an absent file. The file is dead config
> like the rest of the Chromatic surface — no workflow, no token — so it joins the deletion list
> rather than changing the decision.

Removing it also drops the forced `4.1.3 → 5.2.1` major bump from this change's surface.

If visual regression testing is wanted later, adding Chromatic properly — account, project token,
CI job — is its own piece of work.

### 3. Two changes to watch, not pre-empt

**`addon-vitest` setup file became optional in 10.3.** The changelog states "no more setup files
required". `apps/story/.storybook/vitest.setup.ts` currently calls:

```ts
setProjectAnnotations([a11yAnnotations, projectAnnotations])
```

and is wired in via `setupFiles: [".storybook/vitest.setup.ts"]` in `apps/story/vite.config.ts`.

It should continue to work. The plan verifies the suite passes with the file **intact**, and only
then evaluates whether removing it is safe. Deleting it speculatively risks silently dropping the
a11y annotations and the project preview config from test runs, which would not necessarily fail
loudly.

**Resolved during implementation.** The setup file is kept, but the reasoning recorded here was
initially wrong and is corrected: a positive signal does exist in the shipped package.
`@storybook/addon-vitest@10.5.5` detects a setup file containing `setProjectAnnotations`, skips its
own auto-provisioning to avoid conflicts, and logs that the call can safely be removed.

Keeping the file is still the right call — behaviour is byte-identical to 10.1.8 and nothing
regresses — but the real trade-off is narrower than "redundant or not": the hand-written file applies
only `addon-a11y/preview` and `./preview`, whereas auto-provisioning would apply every addon preview
declared in `main.ts`. Removing it would slightly widen what is applied. That is a change worth
making deliberately, in its own PR, not as a side effect of a version bump.

**`componentsManifest`.** Renamed from `experimentalComponentsManifest` in 10.2 (a breaking change)
and defaulted `true`, then defaulted back to `false` in 10.3.5. `.storybook/main.ts` never set
either key, so the repo inherits the default and needs no edit. Recorded because it is the only
hard breaking change in the 10.1 → 10.5 range, and the reason it does not apply is worth knowing.

## Verification

The counts below are the current green baseline and are what the upgrade must reproduce.

1. `bun install` — succeeds; `bun.lock` changes confined to Storybook packages and the removed
   Chromatic subtree.
2. `bun --filter @repo/story test --run` — **exit 0**, `Test Files 299 passed | 6 skipped (305)`,
   `Tests 1228 passed (1228)`, and **no `Errors` line**.
3. The skip count is **exactly 6**.
4. `bun run build` — exit 0, including the Storybook static build.
5. `bun run typecheck` — exit 0.
6. `bun --filter @repo/story dev` — Storybook boots on `localhost:6006` and all five remaining
   addons load: docs, links, a11y, themes, vitest.
7. `bunx biome lint . --max-diagnostics=none` — **`Found 65 errors.` / `Found 412 warnings.`** or
   fewer. Measured immediately before this spec was written. A higher error count means the upgrade
   introduced new lint failures. Always pass `--max-diagnostics=none`; Biome's default cap of 20
   silently truncates the count.
8. `git ls-files | grep -i chromatic` returns nothing, and `grep -rniE "chromatic($|[^A-Za-z])" apps/story .github` returns nothing. A bare `grep -ri chromatic` does NOT work: `packages/ui` has unrelated `chromaticAberration` and `chromaticSpread` props that always match.
9. CI on the PR — `verify` and `storybook` both green.

Three of these carry more weight than the rest:

- **Exit code is a gate independent of the counts.** Vitest exits non-zero on unhandled errors even
  when every test passes. That exact failure mode produced intermittent red CI before, so checking
  counts alone would hide a regression.
- **The skip count must be exactly 6.** Six stories are excluded via `!test` tags — two that fetch an
  absent `.glb` asset, four that need GPU device access. If 10.5 changed tag filtering, those
  silently return and the GPU four fail. A wrong skip count is the earliest signal.
- **Any shift in test counts is a finding, not a new baseline.** 1228 is the number to reconcile
  against. A drop means stories stopped being collected; a rise means exclusions stopped applying.

## Branching

Stack on `chore/repo-hygiene-ci-green` rather than branching from `main`.

That branch carries `retry: 2` in `apps/story/vite.config.ts`, the six `!test` story tags, and the
`ci.yml` workflow that runs this suite at all. Branching from `main` would lose all three, leaving
nothing to verify against.

Consequence: the resulting PR is not mergeable until PR #2 lands. The alternative — merging PR #2
first and branching fresh from `main` — is equally valid and reduces stack depth.

## Out of scope

- termcn and any terminal UI work (see above).
- Adding stories for components that lack them.
- Upgrading `vitest`, `vite`, `playwright`, or React. None is required by Storybook 10.5.5, and
  `playwright@1.57.0` is pinned deliberately.
- The ~65 pre-existing lint errors and the 996 `@repo/story` type errors. Both are documented debt.
- The six excluded stories. They stay excluded for the environment reasons already recorded.
- Setting up Chromatic properly.
