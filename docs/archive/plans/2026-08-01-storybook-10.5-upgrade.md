# Storybook 10.5.5 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `@repo/story` from Storybook `^10.1.8` to `^10.5.5` and remove the unused Chromatic addon, without disturbing the 1228-test browser-mode suite.

**Architecture:** Chromatic comes out first, in its own commit, so that if the suite breaks after the version bump we know the bump caused it. Then the seven Storybook packages move together in lockstep. The diff is small; the work is verification.

**Tech Stack:** Storybook 10.5.5, `@storybook/react-vite`, `@storybook/addon-vitest`, Vitest 4 browser mode, Playwright 1.57 Chromium, Vite 6, Bun workspaces.

**Spec:** `docs/plans/2026-08-01-storybook-10.5-upgrade-design.md`

## Global Constraints

- **Branch:** create `chore/storybook-10.5` **off `chore/repo-hygiene-ci-green`**, not off `main`. That branch carries `retry: 2` in `apps/story/vite.config.ts`, the six `!test` story tags, and the `ci.yml` workflow that runs this suite. Branching from `main` loses all three and leaves nothing to verify against. The resulting PR is not mergeable until PR #2 lands.
- **The green baseline this upgrade must reproduce exactly:** `bun --filter @repo/story test --run` → exit 0, `Test Files 299 passed | 6 skipped (305)`, `Tests 1228 passed (1228)`, and **no `Errors` line**.
- **Exit code is a gate independent of the counts.** Vitest exits non-zero on unhandled errors even when every test passes. Checking counts alone would hide that regression — it is what caused intermittent red CI previously.
- **The skip count must be exactly 6.** Six stories are excluded via `!test` tags: `FluidGlass` and `ModelViewer` (fetch an absent `.glb`), `GhostCursor`, `FaultyTerminal`, `PixelSnow`, `PrismaticBurst` (need GPU device access). A different skip count means tag filtering changed.
- **Any shift in test counts is a finding, not a new baseline.** Reconcile against 1228; do not update the expected number to whatever the run produces.
- **Lint baseline:** `bunx biome lint . --max-diagnostics=none` → `Found 65 errors.` / `Found 412 warnings.` Never omit `--max-diagnostics=none`; Biome's default cap of 20 silently truncates the count.
- Do **not** upgrade `vitest`, `vite`, `playwright`, React or TypeScript. None is required by Storybook 10.5.5. `playwright@1.57.0` is pinned deliberately — CI installs browsers with `working-directory: apps/story` so the installed build number matches the one Vitest launches.
- Do **not** run `storybook upgrade`. Manual edits only. The CLI rewrites config in place and would disturb deliberate customisations in `.storybook/main.ts` and `apps/story/vite.config.ts`.
- Do **not** fix or suppress the 65 pre-existing lint errors or the 996 `@repo/story` type errors. Both are documented debt.
- Do **not** change which stories carry `!test` tags.
- The Storybook suite takes roughly 150 seconds locally. Allow a 15-minute timeout per run and never kill one early — a truncated run is worthless evidence.
- Commits run commitlint (Conventional Commits) and lint-staged via husky.

## Testing note for this plan

There is no new code to test-drive here. The cycle is: **record the baseline, make the change, re-run and reconcile against that baseline.** The suite is the test. Task 4 is the final sweep.

### Task 3: Decide the fate of the vitest setup file

Storybook 10.3 made `addon-vitest`'s setup file optional ("no more setup files required"). This task decides whether ours is now redundant. **The default is to keep it** — removal requires positive evidence, not merely a green suite.

**Files:**
- Read: `apps/story/.storybook/vitest.setup.ts`
- Read: `apps/story/vite.config.ts`
- Modify (only if evidence supports it): both of the above

**Interfaces:**
- Consumes: Task 2's Storybook 10.5.5.
- Produces: either an unchanged setup (documented) or its removal (justified).

- [ ] **Step 1: Read what the file actually does**

`apps/story/.storybook/vitest.setup.ts` currently reads:

```ts
import * as a11yAnnotations from "@storybook/addon-a11y/preview"
import { setProjectAnnotations } from "@storybook/react-vite"
import * as projectAnnotations from "./preview"

setProjectAnnotations([a11yAnnotations, projectAnnotations])
```

It is wired in via `setupFiles: [".storybook/vitest.setup.ts"]` in `apps/story/vite.config.ts`.

It does two things: applies the a11y addon's annotations, and applies the project's own `preview.tsx` config (decorators, globals, and `tags: ["a11y-test"]`).

- [ ] **Step 2: Establish whether a11y checks currently run at all**

This is the crux. A green suite does not prove the annotations are applied — if they silently stop applying, a11y assertions simply stop running and everything still passes.

Run:

```bash
grep -rn "a11y" apps/story/.storybook/preview.tsx
grep -c "a11y" /tmp/sb-1055.log
```

Record both. `preview.tsx` declares `tags: ["a11y-test"]`, which is what activates a11y checks per story.

- [ ] **Step 3: Prove the annotations are load-bearing**

Temporarily comment out the `setupFiles` line in `apps/story/vite.config.ts`:

```ts
          // setupFiles: [".storybook/vitest.setup.ts"],
```

Then run the suite:

```bash
bun --filter @repo/story test --run > /tmp/sb-nosetup.log 2>&1; echo "EXIT=$?"
grep -E "Test Files|Tests |Errors " /tmp/sb-nosetup.log | tail -4
```

Compare against `/tmp/sb-1055.log`:

- **If counts or exit code differ** → the file is load-bearing. **Restore the line immediately** and keep the file. Record the difference.
- **If they are byte-identical** → this is still not sufficient evidence to remove it, because a11y checks failing to run would look exactly like this. Restore the line and keep the file, recording that the outcome was inconclusive.

Either way, restore `setupFiles` before proceeding. The file stays.

- [ ] **Step 4: Confirm the working tree is back to Task 2's state**

Run: `git diff --stat`

Expected: no output. If `vite.config.ts` still shows as modified, revert it with
`git checkout apps/story/vite.config.ts`.

- [ ] **Step 5: Record the decision in the design doc**

Append to the "Two changes to watch, not pre-empt" section of
`docs/plans/2026-08-01-storybook-10.5-upgrade-design.md`, under the setup-file paragraph:

```markdown
**Resolved during implementation.** The setup file is kept. Removing `setupFiles` produced an
identical suite result, but that is not evidence of redundancy: if `setProjectAnnotations` stopped
applying, the a11y annotations and `preview.tsx` config would simply stop being enforced and every
test would still pass. Absent a positive signal that the annotations are applied without it, keeping
four lines of explicit configuration is the cheaper error.
```

If Step 3 instead showed a difference, write that concrete difference here rather than this text.

- [ ] **Step 6: Commit**

```bash
git add docs/plans/2026-08-01-storybook-10.5-upgrade-design.md
git commit -m "docs: record that the vitest setup file is kept

Storybook 10.3 made addon-vitest's setup file optional. Removing
setupFiles produces an identical suite result, but that cannot
distinguish 'redundant' from 'annotations silently stopped applying' --
both look like a green run. Keeping it."
```
