# Dokploy

One Compose service for the whole site: `www`, `blog`, `auth`, `app`, `account` and `api`, built
straight from this public GitHub repo (no registry). SQLite and uploads live on the `api-data`
volume.

1. **Edit `template.toml`'s `[variables]`** (domain, host prefix, Yasmina's address, the branch), then
   regenerate the import string: `bun deploy/dokploy/make-import.ts`.
2. **Dokploy → your project → Create Service → Import**, paste `import.txt`'s contents, confirm.
3. **Advanced → Isolated Deployments: on.** The services reach each other by name only through
   the stack's own network.
4. **DNS:** point `<prefix><app>` for `www`, `blog`, `auth`, `app` and `account` at the server —
   for staging `yas-www`, `yas-blog`, `yas-auth`, `yas-app` and `yas-account` under
   `undefined.guru` (or one `*` record). `host_prefix` in `template.toml` sets the prefix; empty
   gives plain `www.<domain>` for production.
5. **Deploy.** The first build compiles six images on the server; give it at least 8 GB RAM.
6. **Mail:** set `MAIL_PROVIDER=resend` and `RESEND_API_KEY` (or `smtp` + `SMTP_URL`) in
   Environment, then redeploy. Until then mail is only logged and booking confirmations don't arrive.
7. **Admin:** sign up at `https://auth.<domain>/signup` with the `admin_email` address and verify it;
   Yasmina's calendar is at `/admin/bookings`.

Payments run as invoice-only in production (`NEXT_PUBLIC_BOOKING_PAYMENTS` is not set). The
secrets (`API_SERVICE_TOKEN`, `TWO_FACTOR_ENCRYPTION_KEY`) are generated by Dokploy at import;
keep the two-factor key, a new one locks out everyone with two-step verification.

`COOKIE_DOMAIN` is `.<domain>`: the sign-in cookie is shared with every host under that domain, so
on a shared staging domain such as `undefined.guru`, never run anything untrusted on a sibling
subdomain.
