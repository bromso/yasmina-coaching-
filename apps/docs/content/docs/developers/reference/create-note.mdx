Creates a note authored by the API key.

`title` is required, 1-200 characters once leading and trailing spaces are trimmed (it is stored trimmed); `body` is optional, up to 10,000 characters, and defaults to an empty string. Requires the `notes:write` scope.

<Endpoint method={"POST"} path={"/v1/notes"} scope={"notes:write"} />

Send the body as JSON.

## Example request

The example reads your API key from the `API_KEY` environment variable. A key looks like `bb_live_EXAMPLE0_docsOnlyFakeKeyNeverIssuedDoNotUse000000000` — that one is a fake, never issued. {/* gitleaks:allow */}

```bash
curl -X POST "https://api.your-domain.example/v1/notes" \
  -H "Authorization: Bearer $API_KEY" \
  -H "content-type: application/json" \
  -d '{"title":"Quarterly planning","body":"Agenda and decisions from the planning meeting."}'
```

<Callout type="warning" title="Keep your API key secret">
Send the key only in the `Authorization` header, from your own server. Never put it in a URL or a query string, where logs and browser history keep it, and never in browser or mobile app code, where anyone can read it. See [Authentication](/developers/authentication) for creating and revoking keys.
</Callout>

## Errors

Every error answers with a JSON body `{ "error": { "code": "…", "message": "…" } }`. This route can answer:

- `400` `validation_failed` — the body is invalid. The `message` is `Input validation failed` and does not name the field; check the request against the rules in the tables above. A body that is not valid JSON gets `Malformed request. Ensure the request body is properly formatted and the 'Content-Type' header is set correctly.` instead.
- `401` `unauthorized` — the API key is missing, malformed, unknown, revoked or expired, or the key's workspace was deleted or its plan no longer includes API access.
- `403` `forbidden_scope` — the key does not have the `notes:write` scope.
- `413` `validation_failed` — the request body is larger than the API accepts. A body over the server's hard limit may be refused with an empty `413`, with no JSON body.
- `429` `rate_limited` — too many requests with this key, or too many refused attempts from your address; wait the number of seconds in the `Retry-After` header, then retry.
- `500` `internal` — an unexpected error on our side; retry later.
- `503` `internal` — the request took too long to answer. It may still have taken effect, so check before you retry a change.
